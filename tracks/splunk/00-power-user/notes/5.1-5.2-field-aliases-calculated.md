# 5.0 Creating Field Aliases and Calculated Fields (10%)

## 5.1 Describe, create, and use field aliases

A **field alias** is an alternate name for an existing field. Aliases provide
semantic consistency across data sources: when different sources use different
field names for the same concept (e.g., `src_ip` vs. `source_ip` vs.
`client_ip`), an alias lets you refer to all of them uniformly.

**Key characteristics:**
- An alias points to an **existing** field; it does not transform or compute
  values.
- Aliases are created in `props.conf` under the stanza for a source or
  sourcetype.
- Syntax: `FIELDALIAS-<name> = <source_field> AS <alias_name>`
- Multiple aliases can point to the same field.
- Aliases are **search-time** operations (applied when searching, not at
  index time).

**Example:** In `props.conf`:
```
[sourcetype=apache_access]
FIELDALIAS-src_as_client = src_ip AS client_ip
FIELDALIAS-dst_as_server = dst_ip AS server_ip
```

Now searches can use `client_ip` and `server_ip` regardless of the actual field
names in the indexed data.

**Benefits:**
- Normalizes field names across heterogeneous data sources.
- Enables consistent dashboards and saved searches.
- No performance overhead compared to direct field access.

Source: [Field Aliases documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createfieldalias) — Splunk Enterprise/Cloud Platform docs. Accessed 2026-07-19.

## 5.2 Describe, create, and use calculated fields

A **calculated field** is a field whose values are **computed** at search time
using an expression (typically an `eval` expression). Unlike aliases, calculated
fields transform data on the fly.

**Key characteristics:**
- Calculated fields execute an `eval` expression against each event.
- Created in `props.conf` under the source/sourcetype stanza.
- Syntax: `EVAL-<name> = <eval_expression>`
- Computed fields appear alongside extracted fields in search results.
- Examples: derive `profit = price - cost`, or `hours_elapsed = (now() - timestamp)`.

**Example:** In `props.conf`:
```
[sourcetype=transactions]
EVAL-profit = price - cost
EVAL-hours_ago = floor((now() - timestamp) / 3600)
```

Every transaction event now has `profit` and `hours_ago` fields computed
automatically.

**Calculated fields vs. search-time eval:**
- **Calculated fields** (in props.conf): applied to every event matching the
  source/sourcetype, available in all searches.
- **search-time eval** (in the search itself): applied only to the search
  result set, more flexible but requires explicit use in each search.

**Use calculated fields when:**
- A derived field is used in many searches.
- You want consistent definitions across the organization.
- The computation is expensive (cache the result by defining it once).

**Use search-time eval when:**
- The field is specific to one or two searches.
- The transformation is exploratory or experimental.

Source: [Calculated Fields documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Calculatedfieldformulas) — Splunk Enterprise/Cloud Platform docs. Accessed 2026-07-19.
