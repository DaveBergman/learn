# 6.0 Creating Tags and Event Types (10%)

## 6.1 Create and use tags

A **tag** is a **custom label** applied to field values to organize and
categorize data. Tags are primarily used to organize field values into
semantic groups without modifying the data itself.

**Tag characteristics:**
- Tags are **name-value pairs**: a tag name (e.g., `user_type`) applied to a
  field value (e.g., `admin`).
- Created via the UI (Settings → Tags) or in `props.conf`.
- Once tagged, you can search using `tag=tagname` or filter dashboards by tag.
- Tags are **search-time** only; they don't modify indexed data.
- Multiple tags can be assigned to the same field value.

**Example:** Tag the field value `user=admin` with tags `privileged`, `internal`:
- Create tag: `tag=privileged` for `user=admin`.
- In a search: `user=admin tag=privileged` filters to users tagged as privileged.

**Creating tags in props.conf:**
```
[sourcetype=access_log]
ANNOTATE-internal = action:search AS internal_search
```
(Tag definitions vary by Splunk version; UI tagging is the most common method
for certification purposes.)

**Use cases:**
- Classify log sources by environment (prod, staging, test).
- Mark data with sensitivity levels (public, internal, confidential).
- Organize known bad IPs or users across many log types.

Source: [Tags documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Managetags) — Splunk Enterprise/Cloud Platform docs. Accessed 2026-07-19.

## 6.2 Describe event types and their uses

An **event type** is a **saved search** that identifies a category of events
matching certain criteria. Once defined, an event type can be used as a filter
in future searches and dashboards.

**Event type characteristics:**
- Built on a search expression (e.g., `status=500 sourcetype=apache_error`).
- Assigned a name (e.g., `web_errors`, `slow_response`).
- Stored in the Splunk knowledge base (props.conf or eventtypes.conf).
- At search time, you can search `eventtype=web_errors` instead of re-typing the
  full search criteria.
- Event types improve **search reusability** and **naming consistency**.

**Example:** Create an event type `ssl_handshake_failure`:
- Search criteria: `error_code=500 component=ssl message="handshake failed"`
- Name: `ssl_handshake_failure`
- Later: search `eventtype=ssl_handshake_failure` to find all such events.

**Event types vs. tags:**
- **Event types** are based on search criteria (more complex, reusable searches).
- **Tags** are labels on field values (simpler, post-hoc labeling).

**Use cases:**
- Define known anomalies: `eventtype=suspicious_login_pattern`.
- Group related errors across sources.
- Create templates for recurring analysis.

Source: [Event Types documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createeventtypes) — Splunk Enterprise/Cloud Platform docs. Accessed 2026-07-19.

## 6.3 Create an event type

Creating an event type from the UI:
1. Run a search that captures your desired event type.
   Example: `sourcetype=web_access status=500`
2. Click **Save As** → **Event Type** (instead of Saved Search).
3. Name it (e.g., `http_500_errors`).
4. Choose a destination app (e.g., `search`).
5. Save.

Once saved, you can use `eventtype=http_500_errors` in any search.

**Programmatic creation (in eventtypes.conf):**
```
[http_500_errors]
search = sourcetype=web_access status=500

[slow_response]
search = response_time > 5000
```

**Advanced event type features:**
- **Priority** — if an event matches multiple event types, priority determines
  which is reported first.
- **Description** — document what the event type matches.
- **Tags** — event types can have tags applied to them for organization.

Source: [Event Types documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createeventtypes) — Accessed 2026-07-19.
