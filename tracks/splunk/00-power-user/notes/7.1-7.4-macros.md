# 7.0 Creating and Using Macros (10%)

## 7.1 Describe macros

A **macro** is a **reusable fragment of SPL** that can be substituted into
searches. Macros let you define common search patterns once and reuse them
everywhere, improving maintainability and consistency.

**Macro characteristics:**
- Stored in `macros.conf` (search-time) or other Splunk configuration files.
- Called using backtick syntax: `` `macro_name` `` (note the backticks, not
  single quotes).
- Can be **parameterized** (accept arguments).
- Macros are substituted **before** search parsing, so they can contain any
  valid SPL fragment.
- Splunk evaluates the macro's definition and inserts it into the search.

**Example macro definition (in macros.conf):**
```
[simple_error_search]
definition = status=500 OR status=503
```

**Usage in a search:**
```
sourcetype=web `simple_error_search`
```

This expands to: `sourcetype=web status=500 OR status=503`

**Benefits:**
- Centralized logic — define once, use everywhere.
- Consistency — all dashboards/reports using a macro automatically stay in
  sync if you update it.
- Maintainability — easier than copy-pasting the same SPL fragment.

Source: [Macros documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createmacros) — Splunk Enterprise/Cloud Platform docs. Accessed 2026-07-19.

## 7.2 Create and use a basic macro

A basic macro has no parameters. Creation:

1. **Via the UI:** Settings → Advanced Search → Search Macros → New.
2. **Manually in macros.conf:**
   ```
   [my_macro]
   definition = status>=400 status<=599
   ```

**Usage:**
```
sourcetype=apache `my_macro`
```

Expands to: `sourcetype=apache status>=400 status<=599`

**Common patterns for basic macros:**
- Filter expressions: `status=200 OR status=201 OR status=304`
- Time ranges: `earliest=-24h latest=now`
- Field references: `user IN (admin, root, system)`

**Macro scope:**
- Macros defined in the UI are stored in the current app.
- To share macros across apps, define them in the `default` folder or in a
  shared app.

Source: [Macros documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createmacros) — Accessed 2026-07-19.

## 7.3 Define arguments and variables for a macro

Macros can accept **arguments** (parameters), making them dynamic and reusable
across different searches.

**Argument syntax:**
- Arguments are defined as `$arg_name$` in the macro definition.
- When calling the macro, pass arguments in parentheses: `` `macro_name(arg1)` ``

**Example macro with arguments (in macros.conf):**
```
[error_codes]
definition = status=$status_codes$
```

**Usage:**
```
sourcetype=apache `error_codes(500)`
```

Expands to: `sourcetype=apache status=500`

**Multiple arguments:**
```
[status_range]
definition = status>=$min_status$ status<=$max_status$
```

**Usage:**
```
sourcetype=apache `status_range(400, 599)`
```

Expands to: `sourcetype=apache status>=400 status<=599`

**Argument best practices:**
- Use descriptive names for arguments.
- Document what each argument expects (number, field name, etc.).
- Provide examples in comments within the macro definition.

Source: [Macro arguments documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Definesearchmacrosarguments) — Accessed 2026-07-19.

## 7.4 Add and use arguments with a macro

**Creating parameterized macros:**

In `macros.conf`:
```
[timerange_macro]
definition = earliest=$earliest$ latest=$latest$

[user_filter]
definition = user IN ($user_list$)
```

**Calling with arguments:**
```
sourcetype=web `timerange_macro(-24h, now)` `user_filter(admin, root)`
```

Expands to:
```
sourcetype=web earliest=-24h latest=now user IN (admin, root)
```

**Nested macros:**
Macros can call other macros, enabling composition:
```
[all_errors]
definition = `error_codes(400)` OR `error_codes(500)` OR `error_codes(503)`
```

**Argument validation:**
- Splunk does **not** validate argument values at macro definition time.
- Ensure argument values are syntactically correct before calling.
- Invalid arguments may result in syntax errors in the expanded search.

**Example: Practical macro with multiple arguments:**
```
[status_by_host]
definition = status=$status$ host=$host$

Usage:
... | `status_by_host(500, web-prod-01)`
```

Expands to: `... | status=500 host=web-prod-01`

Source: [Macro arguments documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Definesearchmacrosarguments) — Accessed 2026-07-19.
