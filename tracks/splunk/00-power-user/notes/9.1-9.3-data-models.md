# 9.0 Creating Data Models (10%)

## 9.1 Describe the relationship between data models and pivot

A **data model** is a **hierarchical structure** of your data that describes
how events are organized and which fields are available for analysis. Once a
data model is created, **pivot** (Splunk's point-and-click reporting tool) can
use it to generate reports without writing SPL.

**Key relationship:**
- **Data models** define the schema and structure of your data.
- **Pivot** uses data models to generate queries automatically, without needing
  SPL knowledge.
- Pivot is a search accelerator — it translates visual selections into efficient
  SPL behind the scenes.

**Data model structure:**
- **Root object** — the top-level entity (e.g., "Web Traffic", "Network Events").
- **Child objects** — nested groupings (e.g., within "Web Traffic": "HTTP
  Requests", "Web Errors").
- **Fields** — attributes of each object (e.g., status_code, response_time,
  user).

**Pivot and acceleration:**
- Pivots are often powered by **data model acceleration** — Splunk pre-computes
  and caches data model results.
- Acceleration makes pivot queries very fast, even on large datasets.
- Without acceleration, pivots still work but are slower.

**Example data model structure:**
```
Web Application
├── HTTP Requests
│   ├── status_code
│   ├── response_time
│   └── user
└── Web Errors
    ├── error_type
    ├── host
    └── timestamp
```

## 9.2 Identify data model attributes

A **data model attribute** is a field or property within a data model object.
Attributes are what you filter, group, and aggregate on in pivot reports.

**Types of attributes:**

### Field attributes
- Direct mappings to indexed fields.
- **Example:** `host`, `sourcetype`, `status_code`.
- Can be extracted fields or calculated fields.

### Grouped attributes
- Logical groupings of related fields.
- **Example:** A "User" group containing `username`, `user_id`, `user_role`.

### Numeric attributes
- Fields suitable for aggregation (sum, avg, min, max, count).
- **Example:** `response_time`, `bytes_transferred`, `disk_usage`.

### String/categorical attributes
- Fields for filtering and grouping.
- **Example:** `status`, `region`, `department`.

### Timestamp attributes
- Time-based fields used for time series analysis.
- **Example:** `_time`, `event_time`, `log_timestamp`.

**Attributes in pivot:**
When you open pivot for a data model, you select:
- **Rows** — group by an attribute.
- **Columns** — sub-group by another attribute.
- **Values** — aggregate a numeric attribute (count, sum, avg, etc.).
- **Filters** — restrict to specific attribute values.

**Example:** Pivot on the "Web Application" data model:
- Rows: `status_code` (attribute).
- Columns: `user` (attribute).
- Values: Count of events.
- Filter: `response_time > 1000` (attribute).

## 9.3 Create a data model

Creating a data model via the UI:

1. **Settings → Data Models → New Data Model**.
2. **Name:** Assign a name (e.g., "Web Application Events").
3. **Description:** Document the data model's purpose.
4. **Object:** Define the root object (e.g., click "New Object").
   - **Name:** (e.g., "HTTP Requests").
   - **Search constraints:** Specify a base search to narrow the scope:
     ```
     sourcetype=apache OR sourcetype=nginx
     ```
   - Click **Save Object**.

5. **Add attributes:**
   - Within the object, click **Add Field** to add attributes.
   - Select existing fields from your data, or create new calculated fields.
   - Specify the field type (string, number, date, etc.).

6. **Add child objects (optional):**
   - Click **New Child Object** to add sub-objects.
   - Repeat the process.

7. **Save the data model.**

**Example data model creation:**
- **Name:** "Web Traffic"
- **Root Object:** "Requests"
  - Search constraint: `sourcetype=web_access`
  - Fields: `host`, `status_code`, `response_time`, `user`, `method`
- **Child Object:** "Errors" (under "Requests")
  - Search constraint: `status_code>=400`
  - Fields: `error_type`, `error_message`

**Data model acceleration:**
Once created, you can enable acceleration:
1. **Settings → Data Models → select your model → Acceleration**.
2. Click **Accelerate this data model**.
3. Splunk pre-computes results and stores them, making pivot queries fast.

**Best practices for data models:**
- Start with one root object per data model.
- Use consistent field names across objects.
- Add constraints to narrow data scope and improve performance.
- Document the data model's purpose and expected data sources.
- Consider acceleration for large datasets.
