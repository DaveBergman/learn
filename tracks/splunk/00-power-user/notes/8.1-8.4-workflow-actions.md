# 8.0 Creating and Using Workflow Actions (10%)

## 8.1 Describe the function of GET, POST, and Search workflow actions

**Workflow actions** let you extend search results with custom interactions. 
When you click on a field value in a search result, a workflow action can
trigger an external action or a new search.

**Three main types:**

### GET Workflow Action
- Makes an **HTTP GET request** to a URL.
- Useful for querying external APIs, databases, or web services.
- The URL typically includes field values from the clicked event as query
  parameters.
- **Example:** Click on an IP address, send it to an IP reputation service:
  `https://api.reputation.io/check?ip=$click.value$`

### POST Workflow Action
- Makes an **HTTP POST request** with data in the request body.
- Used when you need to send complex payloads or large data.
- Splunk can pass event fields, search results, or static data in the POST body.
- **Example:** Click on a username, POST it to an incident creation system:
  `https://incident-system.internal/create` with body `user=$click.value$`

### Search Workflow Action
- Executes a **new Splunk search** when a field value is clicked.
- Useful for pivoting from one search to a related search.
- The new search can use field values from the clicked event.
- **Example:** Click on a hostname, search for all errors from that host:
  `sourcetype=error host=$click.value$`

**Comparison:**
- **GET/POST** — external integrations (look up data, trigger actions in other
  systems).
- **Search** — stay within Splunk (drill down into related data).

Source: [Workflow Actions documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createworkflowactions) — Splunk Enterprise/Cloud Platform docs. Accessed 2026-07-19.

## 8.2 Create a GET workflow action

Creating a GET workflow action via the UI:

1. **Settings → Fields → Workflow Actions → New**.
2. **Action type:** GET.
3. **Label:** Name the action (shown in the UI, e.g., "Check IP Reputation").
4. **URL:** Specify the target URL with Splunk macro tokens:
   ```
   https://api.example.com/lookup?ip=$click.value$
   ```
   - `$click.value$` — the value of the clicked field.
   - `$click.name$` — the name of the clicked field.
   - `$click.name2$` — alternate field reference.

5. **Field:** Restrict the action to specific fields (e.g., `src_ip`). Leave
   blank for all fields.

6. **Target:** Browser window or new tab (usually leave as default).

7. **Save.**

**Example GET workflow action (checking an IP):**
- Label: "Query IP Reputation"
- Action Type: GET
- URL: `https://www.abuseipdb.com/check?ipAddress=$click.value$`
- Field: `src_ip`

**Usage:** Click an IP in a search result → the workflow action opens the
reputation check in the browser.

**GET best practices:**
- URL-encode special characters if needed.
- Test URLs manually before saving.
- Use HTTPS where possible.

Source: [Workflow Actions documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createworkflowactions) — Accessed 2026-07-19.

## 8.3 Create a POST workflow action

Creating a POST workflow action via the UI:

1. **Settings → Fields → Workflow Actions → New**.
2. **Action type:** POST.
3. **Label:** Name the action (e.g., "Create Ticket").
4. **URL:** Specify the endpoint:
   ```
   https://ticket-system.internal/api/tickets
   ```
5. **POST payload:** Define data to send (JSON, form data, etc.):
   ```
   {"user": "$click.value$", "timestamp": "$click.timestamp$"}
   ```
   Splunk substitutes field values into the payload.

6. **Field:** Restrict the action to specific fields.

7. **Auth (optional):** Provide credentials if the endpoint requires authentication.

8. **Save.**

**Example POST workflow action (creating an incident):**
- Label: "Create Incident"
- Action Type: POST
- URL: `https://incident.company.com/api/incidents`
- Payload:
  ```
  {"affected_user": "$click.value$", "event_source": "splunk"}
  ```

**POST advantages over GET:**
- Can send complex data structures (JSON bodies).
- More secure for sensitive data (not visible in URL).
- Supports authentication headers.

Source: [Workflow Actions documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Createworkflowactions) — Accessed 2026-07-19.

## 8.4 Create a Search workflow action

Creating a Search workflow action via the UI:

1. **Settings → Fields → Workflow Actions → New**.
2. **Action type:** Search.
3. **Label:** Name the action (e.g., "Find All Events for This Host").
4. **Search:** Specify the new search to run:
   ```
   host=$click.value$ sourcetype=*
   ```
   - `$click.value$` — the clicked field's value.
   - `$click.name$` — the clicked field's name.

5. **Field:** Restrict to specific fields (e.g., `host`, `user`). Leave blank
   for all fields.

6. **Target:** Inline search, new window, new tab, or dashboard (usually
   "inline").

7. **Time picker:** Preserve the current time range or use a custom range.

8. **Save.**

**Example Search workflow action (drill down by host):**
- Label: "Show All Events for Host"
- Action Type: Search
- Search: `host=$click.value$`
- Field: `host`
- Target: Inline Search

**Usage:** Click a hostname in a search result → a new search runs showing all
events from that host.

**Search workflow actions are ideal for:**
- Pivoting from summary data to raw events.
- Investigating specific entities (users, hosts, IPs, domains).
- Creating drill-down hierarchies (Region → Host → User).

**Advanced Search workflow actions:**
Can include complex searches with multiple filters:
```
host=$click.value$ status>=400 earliest=$earliest$ latest=$latest$
```
