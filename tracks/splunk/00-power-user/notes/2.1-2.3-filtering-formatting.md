# 2.0 Filtering and Formatting Results (10%)

## 2.1 The `eval` command

`eval` creates new fields in your events using existing fields and an
arbitrary expression.

- Basic syntax: `eval <field>=<expression>[, <field>=<expression>]...`
- If the destination field name already exists, `eval` overwrites its value.
- The expression is case-sensitive; its result **cannot be a Boolean**.
- Field names containing non-alphanumeric characters (other than `_`) must
  be wrapped in single quotes, e.g. a field called `server-1` is referenced
  as `'server-1'`.

Example (from Splunk docs — assigning a human-readable description based on
status code, using `=` to assign and `==` to compare):
```
... | eval description = case(status==200, "OK", status==404, "Not found", status==500, "Internal Server Error")
```

Source: [`eval` command reference](https://docs.splunk.com/Documentation/Splunk/latest/SearchReference/Eval), Splunk docs — accessed 2026-07-18.

## 2.2 Use `search` and `where` to filter results

Both filter results, but differently:

- **`search`** retrieves events from indexes, or filters the results of an
  earlier command in the pipeline. It supports general search expressions
  (e.g. `"foo OR bar NOT field=x"`).
- **`where`** filters using expressions that must evaluate to a **Boolean**
  (true/false) — comparisons like `fieldX!=fieldY` or `numeric_field>500`.
  Critically, `where` can compare **two different fields against each
  other**, which `search` cannot do.
- **Performance**: `search` runs early, on the indexers; `where` runs later,
  on the search head. Filtering earlier (via `search`) reduces network
  traffic and processing load — so prefer `search` over `where` whenever the
  filter can be expressed that way. `where` is typically reserved for
  filtering the result of an aggregation or lookup, where the value being
  compared doesn't exist until after that step runs.

Source: [`where` command reference](https://docs.splunk.com/Documentation/Splunk/latest/SearchReference/Where), classic SPL docs, and [`search` command reference](https://docs.splunk.com/Documentation/Splunk/9.3.1/SearchReference/Search) — accessed 2026-07-18. ## 2.3 The `fillnull` command

`fillnull` replaces null field values with a specified value.

- `value=<string>` sets the replacement; if omitted, the default replacement
  value is `0`.
- A space-delimited field list restricts replacement to those fields; with
  no field list, the value applies to **all** fields.
- Command type: distributable streaming command when a field list is given;
  a dataset-processing command when it isn't.

Example (from Splunk docs):
```
sourcetype="web" | timechart count by host | fillnull value=NULL
```

Source: [`fillnull` command reference](https://docs.splunk.com/Documentation/Splunk/latest/SearchReference/Fillnull), Splunk docs — accessed 2026-07-18.
